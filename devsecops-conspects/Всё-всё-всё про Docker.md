# Как всё было до...

Сервер - цифровой рабочий, который хранит информацию, выполняет задачи и предоставляет результаты по запросу, обсуживая другие устройства и пользователей.

Виртуализация! На одном физическом сервере может быть несколько виртуальных.
На физическом сервере создаётся виртуальная машина: у неё своя система, своё ПО, для неё выделены определенные ресурсы физ. сервера. Если на одном физ. сервере несколько виртуалок, то все они изолированы друг от друга. 

Недостатки VM:
- сниженная эффективность некоторых приложений
- требование полной копии ОС
- при неверном потреблении съедает много ресурсов физ. сервера
- избыточность - для небольшого приложения нужна полная копия ОС

# Контейнеризация
В 2008 появилась технология LXC (Linux Conteiners), которые использовали новые возможности ядра - cgroups и namespaces. Это техническая основа для современной контейнеризации.

Что это?
Технология управления контейнерами. Облегченная виртуализация.

Контейнер использует ядро хостовой системы, а изолируются только приложения, их зависимости, процессы, сет. интерфесы и файловая система, а не целая ОС. 

# Docker
Платформа для создания, запуска и управления контейнеров. Она построена на клиент-серверной архитектуре и использует технологии изоляции ядра Линукс. 

Есть Docker Daemon (докер демон) - главный фоновый процесс, который рулит контейнерами и всем, что с ними связано
API - интерфейс, который обеспечивает обмен запросами и ответами демона с CLI клиентом (командной строкой)

*Условно, мы пишем команду `docker run` в терминал, посредством API выполняется запрос к Демону, Демон выполняет запрос и возвращает результат.*

## Контейнеры и Образы

Для создания контейнеров используются образы (image) - неизменяемые шаблоны, содержащие в себе все необходимые компоненты для запуска приложения в контейнере - исходный код, библиотеки, зависимости и прочее.
Контейнеры создаются как активные копии образов. 
Особенность - слоистая архитектура. Образ состоит из последовательных слоев, которые накладываются друг на друга. Каждый слой - набор изменений файловой системы относительно предыдущего слоя. 

Сами образы хранятся в Registry. Это хранилище образов, оно может быть локальное или корпоративное. Существует самое большое - Docker Hub.

## Команды Docker
Если нам нужен образ из Registry, то мы просто пишем `docker pull <образ:тег>`

Для создания своего образа надо написать Dockerfile = инструкцию по сборке образа. 

```dockerfile
FROM - задаёт базовый образ, например ОС или ЯП
RUN - выполняет команды в процессе сборки образа, например, установка зависимостей
COPY - копирует файл из локальной системы в образ
WORKDIR - задаёт рабочую директорию внутри контейнера
ENV - определяет переменную окружения
CMD - указывает команду, которая будет выполняться при запуске контейнера
```

После написания Dockerfile пишем команду:

```bash
docker build -t myapp:v1 .
```

`-t`: задаёт имя и тег образа
` .`: указывает на **текущую** директорию, в которой находится Dockerfile. 

Проверить наличие образа можно этой командой:

```bash
docker images
```

Теперь, чтобы создать контейнер на основе образа, нужно написать следующую команду:

```bash
docker run -d --name my-container
```

`-d`:  запуск в фоновом режиме, вывода логов не будет
`--name`:  задаёт имя контейнера

> `-` используется для сокращённых команд (например, `--detach` можно сократить до `-d`)
> `--` используется для полных названий команд

Теперь есть запущенный контейнер my-container, который можно увидеть по команде:

```bash
docker ps
docker ps -a
```

`-a`: выводит не только активные (запущенные), но и выключенные контейнеры

Вот, что можно с ним сделать:

```bash
docker stop <имя контейнера> - остановка контейнера
docker start <имя контейнера> - запуск контейнера
docker logs <имя контейнера> - просмотр логов
docker inspect <имя контейнера> - просмотр детальной информации
docker exec <имя контейнера> ... - выполнение команды
docker kill <имя контейнера> - жёстко вырубить 
docker rm <имя контейнера> - удалить
```

## Docker Compose

Инструмент для управления многоконтейнерными приложениями. Позволяет описать конфигурацию всех сервисов приложения в одном файле и управлять ими как единой системой. Все настройки приложения, их образы, сети, переменные окружения и прочее указываются в файле docker-compose.yaml

```
docker compose up - запускает все указанные контейнеры, создаёт необходимые сети и подключает их. 
```
