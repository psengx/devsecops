## Модели OSI и TCP/IP

### OSI
Для описания сложной иерархии сетевых протоколов были созданы разные модели, самая популярная - OSI. Семиуровневая модель сетевого взаимодействия. Модель OSI - учебная и аналитическая схема для понимания, на каком уровне работает та или иная технология.
Каждый из уровней отвечает за свой набор функций.

### TCP/IP
Сам Интернет строится на TCP/IP. Это не просто модель, а набор протоколов, где **IP отвечает за маршрутизацию пакетов**, а TCP и UDP - за транспорт данных. Модель TCP/IP стала практической основой Интернета.

### Протокол IP

В основе Интернет-инфраструктуры лежит **протокол IP**, который присваивает уникальный адрес каждому устройству в сети. Это идентификатор устройства в сети, **по которому направляются данные.** *В IPv4 чуть больше 4 млрд адресов, в IPv6 уже больше.* 

Важным компонентов IP адресации является **маска подсети**. Она определяет какая часть IP-адреса относится к сети, а какая к хосту, позволяет разделить большую сеть на подсети. 

### Система доменных имён - DNS

Она используется, чтобы люди не сталкивались с числовыми IP-адресами. Она переводит понятные адреса сайтов в IP-адрес сервера *(например, yandex.ru -> 192.168.125.0)*. 
>Когда в браузере вводим название сайта, он смотрит свой локальный кэш, проверяя есть ли там IP-адрес для этого доменного имени, а если его там нет, обращается к DNS-серверу, получает нужный айпишник и устанавливает соединение.

### NAT 
Для экономии адресов и удобства в локальных сетях часто применяются приватные IP-адреса и NAT.
NAT позволяет целой группе устройств во внутренней сети использовать **один публичный IP-адрес** для выхода в интернет, подменяя адреса в пакетах на лету. *Так, например, домашний роутер скрывает внешним адресов все устройства.*

### DHCP
**Автоматическую выдачу IP внутри локальной сети** выполняет протокол DHCP. При подключении устройства он сам назначает ему свободный адрес и другие параметры. 

> За **отправку данных по сети** отвечают разные протоколы.
### 1. TCP
Его особенность - он **гарантирует получение** данных. Он устанавливает соединение через трёхэтапное рукопожатие. Как это работает:
1. **SYN.** Клиент, который хочет установить соединение, отправляет серверу специальный пакет с флагом SYN (synchronize). Этот пакет содержит случайное число - начальный порядковый номер для отслеживания сообщений.
2. **SYN-ACK.** Сервер получает SYN-пакет и отвечает пакетом SYN-ACK (acknowledgment). В этом пакете сервер подтверждает получение запроса клиента, увеличивая полученный номер, и отправляет свой собственный SYN с новым случайным порядковым номером. 
3. **ACK.** Клиент отправляет последний пакет с флагом ACK, подтверждая получение SYN-ACK'а от сервера. 
После этого обмена соединение считается установленным. 

**TCP...
- разбивает данные** на пронумерованные пакеты, 
- регулирует скорость передачи, чтобы не перегружать получателя, 
- контролирует доставку каждого пакета 
- и запрашивает повторную отправку потерянных. 
- Далее собирает полученные пакеты в правильном порядке на стороне получателя. 

*Его используют для загрузки веб-страниц, передачи файлов - там, где важно не потерять ни одного байта.* 
### 2. UDP
Его особенность - **быстрая** передача данных, но без гарантий. Он **не устанавливает** соединение перед отправкой данных. Он просто разбивает данные и отправляет их получателю. Не проверяет, дошли ли пакеты, не отправляет повторно потерянный и не контролирует порядок получения пакетов. 

*Его используют там, где важнее скорость, а не надежность (онлайн-трансляции, игры, видео-звонки)*

### 3. ICMP
Нужен для служебных сообщений сети. Не передает пользовательские данные. Также он сообщает об ошибках, например, `timeout`. На нём работают утилиты типа`ping`, которые нужны для диагностики сети. 

**Он работает на 3 (сетевом) уровне модели OSI.**

## HTTP и HTTPS
На верхних уровнях работают протоколы, с которыми сталкиваются пользователи. **Запросы браузера** передаются по протоколу **HTTP**. Именно он определяет, как клиенты сервера обмениваются данными. По HTTP передаются веб-страницы, API-запросы и другое. HTTP **не обеспечивает шифрование**, поэтому используется HTTPS - тот же HTTP, но с шифрованием. 

HTTPS использует **протокол SSL и его преемника TLS** для шифрования данных. Это защищает от прослушивания информации. 

Принцип работы HTTPS основан на **использовании сертификатов**. 
> При подключении к сайту по https сервер отправляет свой ssl или tls сертификат браузеру. Браузер его проверяет на действительность и устанавливается защищённое соединение.

Это обеспечивает конфиденциальность и целостность передаваемой информации. 

# Сетевые устройства
## 1. Switch - коммутатор
Соединяет компьютеры в одну локальную сеть и передаёт данные между ними, используя **MAC-адреса**.
## 2. Router - маршрутизатор
Соединяет между собой разные сети. Роутеры для передачи данных используют **IP-адреса.**
## 3. Firewall - межсетевой экран
Проверяет проходящий через него трафик и блокирует нежелательные соединения. 
## 4. VLAN - Virtual LAN
Позволяет **разделить физическую сеть** на несколько изолированных сегментов. Простой способ, например, *отделить гостевой Wi-Fi от основной сети компании.* 


> В глобальном масштабе интернета критически важен протокол
## BGP - Border Gateway Protocol
Связывает автономные системы - крупные сегменты интернета. Отвечает за обмен сведениями о доступных маршрутах между автономными системами. 

# Немного про ИБ
## VPN
Технология, которая создает защищенный тоннель в интернете.  При использовании VPN данные шифруются, отправляются на VPN-сервер, сервер расшифровывает данные и отправляет куда надо.

Также это ранее упомянутые HTTPS, VLAN, Брендмауэры (Firewall).

> Сегодня используются два принципа:
## 1. Defense in Depth (многоуровневая защита)
Создание нескольких слоёв защиты
## 2. Zero Trust (нулевое доверие)
Подход, при котором каждый запрос проверяется, независимо от источника поступления.

## Виртуальные сетевые драйверы

### Docker
По умолчанию создает сеть `bridge`, давая контейнерам внутренние IP и переводя их наружу через NAT. 
### Кластеризация 
Kuber использует концепцию *"каждый Pod имеет свой IP"*. Он автоматически настраивает сеть так, что все контейнеры смогут обмениваться данными, даже находясь на разных узлах кластера.
